# 0113. Town levels, difficulty levels, the tutorial and the music as data

**Status:** Implemented for review (2026-10-23). Requested by Guillaume ("town and difficulty levels, the tutorial and the music are the next thing to put in data driven if possible"); the last part of step 3 of [0093](0093-data-driven-content-and-authoring-tools.md), after [0107](0107-text-in-json-files.md)–[0110](0110-every-island-has-a-file.md). Guillaume then approved one list of every sound (effects as audio files, music as a file or the generated theme) and asked that the tutorial format work for quests later; both are part of this decision.

## Context

After 0108 and 0109, goods, weather kinds and ships were data, but four things were still lists in TypeScript: the four town levels (`SettlementLevel = 1 | 2 | 3 | 4`, `MAX_SETTLEMENT_LEVEL`, with "4" written into the editors and checks), the three difficulty levels (`DIFFICULTIES`, with the New voyage cards and the Settings buttons written by hand in `index.html`), the nine tutorial lessons (`TUTORIAL_STEPS` and a state machine that named steps in every method) and the music theme. Each level's numbers were already in `economy.json` and `difficulty.json` ([0094](0094-tuning-moved-to-data.md)).

## Decision

1. **Town levels: `src/data/town-levels.json`.** `levels` lists the levels from the smallest, each with its English `name` (the game shows `settlement.level.<n>` from the text files when there is one, like goods); `startLevel` is the level of a port whose map entry has none (2, the village). `MAX_SETTLEMENT_LEVEL`, `SETTLEMENT_LEVELS`, the map editor's level lists, the island builder's level buttons and checks, and the map and island checks all come from it. The per-level numbers stay in `economy.json` › `towns`, where the tuning panel will find them; a test checks every per-level table has one entry per level. The rare-goods gate of [0065](0065-rare-goods-from-the-far-yards.md) holds the step into the **top** level. The hand-built town looks of [0060](0060-growing-town-visuals.md) stop at 4: a higher level looks like a port town until its island file gives it props of its own.
2. **Difficulty levels: the entries of `difficulty.json` › `levels`**, easiest first (the order "easiest level played" uses). Each entry now also has `name`, `tag` (its one-line pitch), `color` and `waves` for its card; `default` names the level that plays when none is picked or saved and keeps the map's own weather (Captain). The New voyage cards and the Settings level switch are built from the file (`src/ui/levelCards.ts`): text from `level.<id>`, `level.<id>Tag` and the points `level.<id>1`, `level.<id>2`… while they exist; a level not translated yet shows its file `name` and `tag`. The Fair winds press hint now follows the knob (`cargoLost` 0) rather than the level's id.
3. **Tutorial: the first quest, `src/data/quests/first-voyage.json`.** Guillaume asked whether the format could serve quests, so the file is quest-shaped: `id`, `name`, `start` (when it begins: `offered`, offered on a fresh voyage and from the menu), `text` (prefix of its text keys, `lesson`), `reward` (`gold`, paid once on finishing; 0 for the tutorial) and `steps`. The lessons are the steps, in order. A step says which harbour it is about (`port`: origin or delivery), which one a pick on the chart sets (`picks`), whether it follows the cargo, when it shows Continue, where the coach mark points (`pointer`, `pointerGood`, and per surface `coach`), and in `on` which step each event leads to (`done` finishes). The events are a small library in `src/sim/tutorial.ts`, like ship parts: `chart-opened`, `port-picked`, `destination-cleared`, `sails-practised`, `continue`, `docked`, `left-port`, `bought`, `sold`, `cargo-gone`, `cargo-sold`. Step text is `lesson.<id>.title`, `.copy` and `.continue`, and every step can use `{origin}`, `{delivery}`, `{cargo}`, `{good}` and `{buyer}`. The engine still runs this one quest with its own saved progress (`fwt.tutorial.v1.<map>`); more quests, other starts and rewards come when quests are built.
4. **Music and sounds: `src/data/audio.json` lists every sound.** `music.sea` is the track played at sea and `effects.creak` the hull creak of [0078](0078-press-warning.md). A track is either `{ "theme": "<file>" }`, composed live from a theme in `src/data/music/`, or `{ "file": "audio/<name>.mp3" }`, a recording in `public/` that loops; an effect is either `{ "synth": "creak" }` (made in `sfx.ts`) or `{ "file": … }`, decoded once on the first tap. `volume` scales a sound. The theme file `src/data/music/fair-winds.json` holds what makes the tune: tempo, scales and keys, bar rhythms, chord progressions, start steps, range, leap and moves of the melody, rest chance, accents, pad and bass loudness, the pad bars between tunes and the echo. The form (AABB in 6/8, cadences, chord tones on strong beats) and the instruments (`synth.ts`) stay code. A missing or broken file plays as silence.
5. **Proof that nothing changed.** `tests/plays-the-same.test.ts` was written and its hashes taken **on the code before the move**: 200 tunes by seed, every difficulty level's knobs, order and weather, the town level names in English and French, and 300 random tutorial sessions (66,000 recorded states: step, ports, cargo, pointers, lesson text, course and storm hold after every call). They pass unchanged after it. `tests/difficulty-cards.test.ts` checks the generated cards and buttons have the same markup as the hand-written ones (`tests/fixtures/difficulty-markup-0083.html`). `tests/levels-as-data.test.ts` adds a fourth difficulty level and a fifth town level in the files only; `tests/tutorial-data.test.ts` checks the quest file, drops the wind lesson and pays a reward from the file only; `tests/audio-data.test.ts` checks the sound list and composes a new theme from data only.
6. How to add a level, a lesson, a theme or a sound: [docs/content/README.md](../content/README.md).

## Consequences

- No gameplay or visual change, as the tests above show.
- A fourth difficulty level is one entry in `difficulty.json` (plus its text when translated). A fifth town level is one entry in `town-levels.json` and one number in each per-level table of `economy.json` (growth, wants, makes, order size); islands can give it props from the island builder.
- Lessons can be reordered, removed or added from existing events in the file; a lesson needing a new kind of event (reefing in a gale, say) needs code once. Later quests can use the same file format; running several needs the quest engine (start triggers, progress per quest, a quest list).
- A new tune is a theme file and one line in `audio.json`; a recorded track or effect is a file in `public/audio/` and one line. The service worker does not pre-cache recordings yet.
- Saves are unchanged: difficulty ids, town level numbers and tutorial step ids are stored as before. Renaming a shipped difficulty or lesson id would reset that choice in old saves.
- Still in code by choice: what each tutorial event watches, the town looks of the four hand-built port profiles, and the game rules themselves.
